# M3 平台化方向：协作稳定性 + agent 任务效率

> 2026-11-04 14:0x。用户澄清项目定位：**这是"agent 与人共同在 CAD 文档里协作"的平台**，具体需求多样、无法预先做成功能 ⇒ 优化目标只有两个：**协作稳定性**、**agent 完成任务效率**。
> 本文基于本机实测（非估算），把两个目标拆成可测指标、指出当前瓶颈、给出 M3 方案。

---

## 一、先量化（实测，2026-11-04 14:0x）

### 1.1 每命令地板价 ≈ 4.0 s —— 当前最大效率瓶颈

| 测量项 | 实测 |
|---|---|
| 裸 `powershell -NoProfile -Command exit` | **1,856 ms** |
| `cad.ps1 doctor`（无 CAD，helper 立即返回） | **4,165 ms** |
| `cad.ps1 status` × 6（已附着，helper 本体 ~30 ms） | 4,174 / 3,960 / 3,814 / 3,827 / 3,954 / 4,467 ms（**avg 4,033 ms，min 3,814 ms**） |

⇒ helper 干活只要 25–50 ms，**> 97% 的时间花在"进程/脚本/编译缓存检查/JSON 往返"上**。
⇒ agent 一个任务通常 5–15 条命令 ⇒ 纯开销 20–60 s；这是"效率"问题的第一顺位。

### 1.2 大图读一次 209 s（624 实体真实水系图，中望 Classic 16）

| 场景 | 实体 | helper 耗时 | 说明 |
|---|---|---|---|
| 断面图（我们自己画的） | 87 | **217–303 ms** | ~3 ms/实体 |
| 真实示例水系图（只读打开） | 624 | **208,838 ms（≈209 s）** | `readPath:"com"`，≈335 ms/实体 |

⇒ 不是线性增长，是**属性读失败后的重试放大**（helper 对读空/失败的属性做 6×60 ms 重试；水系图里块参照/复杂实体占 116 个，每失败一次 ~0.36 s）。
⇒ 结论：**读必须分级**（句柄级 / 摘要级 / 几何级），且"失败不重试同一属性 6 次"，并优先走 LISP 一次性拼串（Classic 有变量桥、2025/ACAD2007 没有，要按能力降级）。

### 1.3 写侧已经够快（不是瓶颈）

84–87 实体画一条命令：Classic 569–662 ms、ACAD 631 ms、2025 2281 ms；undo 一次 194–543 ms。⇒ 写侧不需要再优化，优化重点在**读**和**每命令地板价**。

## 二、平台需要什么（而不是"功能"）

用户需求多样 ⇒ 平台应提供**正交原语**，让 agent 自己组合出任意任务：

| 原语 | 作用 | 现状 |
|---|---|---|
| `read`（分级） | agent 的"眼睛"：列表/摘要/几何，分页 | 有，但**无分级、大图 209 s** |
| `query` / `select` | 按图层/类型/bbox/文字/属性过滤，返回句柄 | **缺**（现在只能全读再让 LLM 过滤，token 爆炸） |
| `entity`（通用写） | add/update/delete/move/copy，锚点+回读+回滚 | **缺**（现在只有 section 专用写） |
| `plan / apply / verify` | 三阶段事务：先 dry-run 出计划 → 应用 → 回读断言 | **部分**（section 内部有，未通用化） |
| `diff` / `snapshot` | "这一轮到底改了什么" | **缺**（undo 只有组计数） |
| `session` / `busy` / `lock` | 会话锚定、忙态、写互斥、handoff | 部分（state.json + 忙检查，无锁） |
| `render`（改区/整图） | 人眼可验 | **缺**（M2 未做，`MSpace` 不可写需换通道） |
| 能力探测/降级 | 三产品差异透明化 | 已有（doctor/progid/产品探测） |

## 三、稳定性威胁清单（多数已踩过，按"会不会伤人"排序）

| # | 威胁 | 当前状态 | 需要补的 |
|---|---|---|---|
| 1 | 用户在操作（命令进行中/拖拽/模态框）时 agent 写入 | 有 BUSY 前置检查 + WaitIdle + MessageFilter | **可恢复性**：拒绝时的重试策略、给用户的可见提示 |
| 2 | 撤销栈与用户共享 | 每批一组 undo；实测有效 | **跨命令事务语义**：多命令要不要合成一组；"用户自己 Ctrl+Z 了"怎么检测 |
| 3 | 实例/产品歧义（3 个产品、ProgID 动态改写） | 已按进程探测 + MULTI_PRODUCT | 多实例同一产品的归属（按 pid）已做，够用 |
| 4 | 命令串 2 KB 静默失败 / 语法错污染提示符 | 已分片 + LASTPROMPT 校验 | **恢复动作**：污染后如何清场（ESC/重置提示符）要固化 |
| 5 | 长会话锚点漂移（用户切图、改图、切布局、缩放） | 有 fingerprint/changedOutside | **每次写前重新锚定 + 变化告知**，不能假设句柄还有效 |
| 6 | 大图/只读/加密文件 | 只读有 ReadOnly 判定 | 只读模式下的"草稿层"策略（写到临时图再合并？）待设计 |
| 7 | CAD 挂死（实测：`Regen` 曾把实例搞死、wedged 实例使 undo 失效） | 已移除 Regen、加了 BUSY 检查 | **实例隔离 + 自动恢复**（检测 hung → 提示用户 → 重建会话，保留证据） |
| 8 | 多 agent/多任务并发写同一图纸 | 无锁（靠纪律） | **文档级命名互斥锁**（`Local\cad-doc-<sha16>`） |

## 四、效率威胁清单（按实测排序）

| # | 成本 | 实测 | 对策（目标） |
|---|---|---|---|
| 1 | 每命令 4.0 s 地板价 | 见 §1.1 | **常驻 daemon**（管道往返 1–15 ms）+ 入口不再起 PS（或常驻宿主调用） → **目标 <0.6 s/命令** |
| 2 | 大图读 209 s | 见 §1.2 | **分级读**：`-Handles`（只回句柄/类型/图层，LISP 拼串）→ ~1 s；`-Summary`（加 bbox）；`-Geom` 才取顶点，且分页（`-Limit/-Cursor`） |
| 3 | 读回 JSON 进上下文的 token | 624 实体 read ≈ 239 KB JSON | **摘要优先**（按图层/类型计数 + 抽样 + 句柄列表）；明细分页按需取 |
| 4 | 迭代步数（读→改→验 3 步/轮） | — | `plan/apply/verify` 一条命令完成一轮；`diff` 一条命令出账 |
| 5 | 失败重试成本 | 209 s 里有大量属性重试 | 失败一次就降级（记 warning），不 6×60 ms 死磕同一属性 |

## 五、M3 建议方案（按"先解决最痛的"排序）

### E1 性能底座（最高优先，影响所有任务）
1. 常驻 daemon（照 WPS 版的 PipeServer：4 字节长度 + UTF-8 JSON，一请求一连接，`-Mta` 入口 / STA helper），编译缓存已有。
2. `read` 分级 + 分页 + 失败降级；Classic 走 LISP 拼串快路径，2025/ACAD 走 COM 但只读必要属性。
3. 目标：`status` < 600 ms；`read -Handles` 624 实体 < 1.5 s；`read -Geom` 624 实体 < 10 s。

### E2 通用写原语（平台化核心）
`entity -Items`（add/update/delete/move/copy，锚点指纹 + 回读 + 整体回滚）+ `query`（过滤/分页/句柄）+ `plan/apply/verify` 三阶段 + `diff`。

### E3 稳定性骨架
忙态可恢复、提示符清场、写前重锚定、文档级锁、挂死检测与恢复；再配 **chaos 测试**（模拟用户拖拽/模态框/切图/改图/断电式中断）。

### E4 度量与回归（决定"能不能持续优化"）
建 **20 条真实 CAD 任务基准集**（不是预设功能，而是"改标注/查数量/换图层/出图/统计"这类自由任务），度量：成功率、平均命令数、平均墙钟、失败模式分类。之后每次优化都用它跑一遍。

---

## 六、建议的第一步

**先把 E1 + E4 一起做**（性能底座 + 基准集）：
- 理由：效率瓶颈已经实测钉死（4 s/命令、大图 209 s），做完立刻让所有任务变快；
- 基准集是"平台化"的前提——没有它，任何"稳定性/效率"改进都无法量化；
- 之后再上 E2/E3（通用原语与稳定性），因为它们需要 daemon 的低延迟做支撑（一条任务内几十次原语调用）。

预期效果：一类典型任务（例如"把 30 处标注按规则改一遍并核对"）从 **~15 条命令 × 4 s ≈ 60 s 开销** 降到 **~15 × 0.4 s ≈ 6 s**，大图读取从 209 s 降到秒级。
