# 结论：agent 与中望 CAD 协作的 skill —— 可行，且工程成本低于 wps-office-cooperate

> 日期：2026-11-04（本机实测）｜口径：用户三条要求 = ① 只要「用户开着图纸、agent 当场改」的实时协作；② 场景 = 按数据画图 / 图纸校对 / 改图 / 信息提取统计；③ 兼容多版本，不绑死某一版。
> 本文是**汇总裁决**，三份证据文档：`research/com-probe.md`（本机实测）、`research/api-surface.md`（API 面与版本）、`research/pattern.md`（WPS 骨架提炼 + 命令面草案）。

---

## 一句话

**能做，而且 CAD 这一侧比 WPS 那一侧好做**：跨进程 COM 往返 0.47–0.9 ms（WPS 约 130 ms/条），10000 条线一条命令 152 ms，撤销组天然有效，干净退出 0 残留。真正要小心的不是"快不快"，而是**三件与 CAD 特有环境有关的事**：单条命令 2 KB 上限且超限静默失败、CAD 写出的 .dxf 被单位透明加密、v16 没有 .NET / 没有 AddTable / 没有截图 API。

## 一、决定可行性的六条实测证据

| # | 能力 | 实测数字 | 为什么关键 |
|---|---|---|---|
| 1 | **附着用户已开的 CAD** | `Marshal.GetActiveObject("ZWCAD.Application")` **191 ms**，拿到的 HWND 与用户实例一致；第二次 `CreateObject` **复用同一实例**（进程 1→1） | 这是「当场改」的地基。附着便宜 ⇒ 不会为了连上就等好几秒 |
| 2 | **跨进程写一次往返** | `SendCommand` + `GetLispVariable` 往返 **10 ms** | 决定"一条命令多次交互"是否可行（WPS 版当年是 130 ms/条，才逼出 daemon） |
| 3 | **画图吞吐** | 一条 `SendCommand` 画 **10000 条线 = 152 ms**；COM 逐实体 `AddLine` 0.6–0.9 ms/个（1000 个≈1 s） | 「按数据画图」这个场景的性能完全不是问题，1 万个图元秒级 |
| 4 | **可回退** | `StartUndoMark/EndUndoMark` 把 10 次 COM 编辑合成 **1 步**；一条 `SendCommand` 天然 1 步；`_.U` 一次整体回退（delta=0）。U4 复测：每个 mark 恰好 = 1 步 | **比 Word 修订模式更干脆**：不需要 journal 撑基本盘，用户 Ctrl+Z 就是一次干净回退 |
| 5 | **读全图** | LISP 一次性拼串：11000 实体 **仅句柄 0.52 s** / 全字段 CSV **3.7 s**；COM 枚举 11000 实体 5.4 s | 读侧有"一次取全"通道，且**完全绕开文件系统**（见下面加密那条） |
| 6 | **干净收尾** | `doc.Close($false)` + `app.Quit()` = **5.4–6.9 s，0 残留进程** | 满足"不得在用户机上留一堆 CAD 进程"的硬要求（`Quit()` 单独调用会卡在"是否保存"模态框里，必须先进 `Close($false)`） |

**附带确认**：`SetWindowText(app.HWND, "… [AI-COLLAB]")` 实测能在窗口标题上看到（与 WPS 的〔AI〕标记同一套路）；多文档 `Documents.Add/Activate` 可用；`ModelSpace.Count` 与 ezdxf 解析 DXF **105=105 且类型完全一致**（AC1021/R2007）。

## 二、四条硬约束（不解决就会做出一个"看起来能跑、实际会坑用户"的 skill）

1. **`EvaluateLispExpression` 与 `app.Eval` 都是空壳**（`E_NOTIMPL` / `RPC_E_SERVERFAULT`）。
   → 唯一 LISP 通道 = `SendCommand` 发短命令 + `GetLispVariable` 取回**标量**（数字/字符串；**列表传不回来** `E_INVALIDARG`）。
   → 结论：**不能指望"一次调用算完并返回结构体"**；要么用 LISP 把结果拼成字符串（实测 288 KB 字符串可回传，3.7 s），要么写临时文件。
   → 注意：网上/官方 IDL 里 `IIcadDocument.EvaluateLispExpression` 声明得漂漂亮亮，**IDL 有 ≠ 实现**——这条是本次最有价值的纠错。

2. **单条 `SendCommand` 上限 ≈ 2 KB，且超限静默失败**（1944 字符 ✅ / 3864 字符 ❌，无报错、无异常）。
   → 所有"生成 LISP 文本发过去"的路径必须**分片 ≤2 KB**；且每条发送后读 `LASTPROMPT` 校验，否则会出现"以为画了 500 条、实际一条没画"。
   → 反过来：**用循环写短命令**没问题（`(repeat 10000 …)` 只要命令文本短，152 ms 就画完 10000 条）——2 KB 约束的是**文本长度**，不是**工作量**。这是设计上的关键分水岭。

3. **单位透明加密（Agile DGS）按扩展名生效**：CAD 写出的 `.dxf` **是密文**（头 `17DA5FA01633CD9A`）；同内容写成 `.txt` 是明文；写进 `<workdir>` 的 `.txt` 曾 15 s 超时失败，写 `%TEMP%` 正常。
   → **所有中间文件一律落 `%TEMP%`**；**读侧首选 LISP 内存拼串（不落盘 ⇒ 不会被加密）**；DXF 只作审计旁路，用到时必须先解密（本机已有 `decrypt-cad-image` 技能）。
   → 这条也解释了为什么"离线改 DWG 文件"的路线不可行：落盘即密文，且 DWG 私有格式没法安全回灌。

4. **v16（2016 经典版）的能力缺口**：无 .NET 托管 API（2019/2021+ 才有，不能当共同面）、无 `AddTable`（`IIcadTable` 是空接口，单元格读不到）、无 `AddMLeader`、无 Field、无动态块属性读写、无 `Publish`、`SaveAs` 最高 2007 格式、32 位进程、**`IsQuiescent` 不可靠**（30000 实体批量期间仍报 True）。
   → 忙闲检测不能用 `IsQuiescent`，要用 `GetVariable("CMDACTIVE")` + `LASTPROMPT` 文本判据，并自己串行化所有写入。
   → **会签栏若是动态块，属性可能读不全**——这是场景②（图纸校对）唯一的高风险点，必须在试点前先验一张真实图纸的图框块类型。

## 三、架构：WPS 那句"骨架"能复用多少

**可复用（约 50–60% 工程量，与业务无关的工程骨架）**：入口包装器、常驻 helper/daemon、命名管道协议、单段 JSON 信封（`ok/data/error/warnings/elapsedMs`）、`hint`-托盘-标题标记、源码哈希编译缓存、publish 脚本、测试 runner、PS 5.1 编码门禁。

**必须改（CAD 的前提变了）**：

| WPS 的做法 | CAD 版的做法 | 理由 |
|---|---|---|
| 花大力气"减少 COM 往返"（`WordOpenXML` 一次取全、批量块） | 不必那么拼：往返 0.5 ms，**反而要花力气在"命令文本 2 KB 分片"和"失败可感知"** | 瓶颈换了位置 |
| Word 修订模式当"天然可回退" | `StartUndoMark/EndUndoMark` 包一个撤销组 + 写前快照 + **绝不隐式保存** | CAD 没有修订层，但 undo 分组实测有效 |
| 段号 + `expect` 文本寻址 | **Handle + 多维指纹**（类型/图层/首点/文字哈希），支持 `relocated:true` | 图形没有"文档序"；块内实体/XREF 不在 `ModelSpace.Count` 里 |
| 每页 EMF 渲染（毫秒级、不动窗口） | **改区渲 / 落盘前整图 Plot→PDF 一次**；渲前保存、渲后恢复用户视口 | CAD 出图是秒级/页，且 `ZoomExtents` 会把用户眼前的图挪走 |
| 图上批注/页上药丸 | **明确不做图上标记**（会进打印、进工程量、进他人参照） | 污染面不可接受 |
| 状态栏承诺可见 | 只用标题前缀 + 托盘 + 气泡；`StatusBar` 可写但不承诺用户看得见 | 与 WPS 的诚实结论一致 |

**通道分工（实测支撑）**：
- 写：**COM 逐实体/选择集批量**（0.6–0.9 ms/个；`SelectionSet.Select`+`Erase` 一次删 11000 个 = 2.1 s）为主；LISP 循环（文本 ≤2 KB）用于"一次画一批"；原生命令只在必需时用短 `SendCommand`。
- 读：**LISP 一次性拼串**（句柄清单 0.52 s / 全字段 CSV 3.7 s，11000 实体）为主；COM 枚举做小图与对照；DXF 导出（`SaveAs` 142 ms/1.7 MB）只作审计旁路且需解密。
- 核：`Plot.PlotToFile` → PDF → 栅格化（语义最真，含打印样式）；`PrintWindow` 截图（无 COM 截图 API）作快速目视；结构化核对（句柄/属性/包围盒/图层计数）作机械判据。
- 版本：`GetVariable("ACADVER"/"ZWCADVER")` + IDispatch 方法存在性探测，**晚绑定 + try 降级**，不碰 .NET / ZRX。

## 四、四个业务场景的可行性打分

| 场景 | 判断 | 依据与限制 |
|---|---|---|
| **① 按数据画图（断面图/工程量图）** | ★★★★★ 强匹配 | 10000 图元 152 ms；难点只在"单位与比例上下文"（`DIMSCALE/LTSCALE/INSUNITS/当前文字样式`）必须先读再算，否则字高/标注看着就错 |
| **② 图纸校对（图层/线型/文字/标注/图框）** | ★★★★☆ 强匹配，风险最低 | 规则机械、可先只读出报告（零风险起步）。**风险点**：表格内容（无 `AddTable`）读不到；动态块会签栏属性可能读不全 → 试点前先验一张真实图框 |
| **③ 改图/编辑现有图纸** | ★★★☆☆ 可行但要有纪律 | undo 分组实测有效（一步撤销）；但**保存后撤销栈是否清空未测**，且"误删不可逆" ⇒ 默认只增不改、改动即一组 undo、保存必须用户点头 |
| **④ 信息提取与统计** | ★★★★★ 强匹配 | 11000 实体全字段 3.7 s；比人工翻图快两个数量级，且可导出 CSV/Excel 回填报告 |

## 五、分阶段落地（已按用户决策调整）

- **M0 探针**（已完成）：能力表、成本模型、坑三条已落盘。
- **M1 最小闭环（进行中）**：`doctor / status / open / info / read / section / undo / hint / finish` —— 以**断面图**为首个场景，接口冻结在 [DESIGN-M1.md](../DESIGN-M1.md)。
  → 验收标准：**给一张 Excel 断面数据，在用户开着的图纸里画出断面（地面线/水位线/高程与点号/基线/深泓点），一次撤销全撤，不落盘，收尾 0 残留进程**。
- **M2 场景命令**：`audit`（图层/文字/标注/线宽规则 + `-ExitCode` 门禁）、`measure`（长度/面积/工程量，闭合性单列）、`text`/`dim` 批量、`render`/`plot`。**不做 `frame`（图框/会签栏）**。
- **M3 工程化**：常驻 daemon、2 KB 分片器、`LASTPROMPT` 校验、TEMP 文件与加密规避、版本探测降级、回归测试、`publish.ps1`。
- **M4 AutoCAD 兼容**：`-App autocad` + ProgID `AutoCAD.Application` 探测；两家的 `SendCommand` 同步语义与 LISP 回传差异要单独实测（AutoCAD 的 `EvaluateLispExpression` 实装，可作快路径）。
- **M5 跨中望版本**：用真实 2019/2024 环境跑同一套回归，验证晚绑定 + 能力探测降级。

## 六、决策已定（2026-11-04 用户拍板）

| 事项 | 决定 | 对设计的影响 |
|---|---|---|
| 版本范围 | 公司**同时用中望 CAD 与 AutoCAD，且两边都有多个版本** | 跨版本是硬需求：只走 COM 晚绑定 + LISP 短命令 + ProgID 探测，不碰 .NET/ZRX；命令面只用两家交集 |
| AutoCAD | **放第二阶段（M4）**，功能后做 | 架构预留 `-App zwcad\|autocad` 探测分支，M1 只实测中望 2016 |
| 图框/会签栏 | **不需要** | 删掉 `frame` 命令与动态块属性相关设计，场景②只做图层/线型/文字/标注规则 |
| 操作纪律 | 默认不保存、改动一步可撤销、图上不留 AI 标记 | 写侧只做 Undo 组 + 回读校验；不做图上批注/药丸；`finish` 不落盘 |
| 首个场景 | **断面图**（Excel 起点距↔高程） | M1 的 `section` 命令成为验收主战场（见 `DESIGN-M1.md`） |
| 绘图约定 | 比例/图幅/水位**由参数指定、带默认值** | 默认 hScale=500 / vScale=50 / A3；超宽自动升档并可 `-NoAutoScale` 关闭 |

## 附：一句话回答"你觉得可行吗"

**可行，且性价比比 WPS 版更高**：WPS 版最难的是"COM 太慢"，CAD 这边 COM 快两个数量级、撤销组天然可用；真正的新风险全部来自 CAD 特有的三件事——**命令串 2 KB 静默截断、图纸文件被透明加密、老版本 API 缺口**。这三条都已经在探针里被实测钉死，因此不是"可能踩坑"，而是"已知怎么绕"。
